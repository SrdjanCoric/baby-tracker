Decision map · unified timer contract

Enter times, not arithmetic

Every manual entry and every edit asks for a duration in minutes. A caregiver who knows the baby woke at 5:30 and reached the phone at 5:43 has to subtract by hand. These forms ask for a start time and an end time instead, and show the duration they imply.

Added

End Time, built from the date and time pills the start already uses, so it inherits the same picker, the same formatting, and the same 12/24-hour preference.

Its date pill matters: a night sleep starting 11:40 PM ends on the following day, which a minutes field never had to express.

Removed

Duration (minutes) and the Quick Durations chips (15/30/45/60/90/120 for sleep). Duration becomes a derived readout, not an input, so one entry can no longer carry a duration that disagrees with its own times.

The two-tap "30 minute nap" path goes with them. That is the cost of this change.

Unchanged

Start Time, Notes, the save button, and every activity-specific field — bottle volume, breast side, food type — keep their current position and behavior.

What the form still has to answer

Shape is settled above. These are the rules behind it, and they are what the decision record has to state before anyone plans the work.

  • Bounds. An end before its start is already rejected by validateSleepEndTime. What is not decided: whether an end in the future is allowed, and whether an edit may push two entries into an overlap the running-timer start edit clamps against.
  • The minimum. Timers under 60 seconds are discarded in production. A manual entry that lands inside the same window has no such rule today.
  • Paused entries. A sleep recorded before the pause change stores a duration shorter than its own interval. Opening it in this form shows a duration that disagrees with the one on its Timeline row, and saving would silently correct it.
  • Sleep type and classification. Moving a start across the day boundary changes what the entry is. The stored morningClassification is written only at stop and on a type change, and no path recomputes it when times move.
  • The wake-window reminder. Editing an end fires on_sleep_update_last_ended, which recomputes babies.last_sleep_ended_at and moves a scheduled push. A time edit is not a client-only change.
