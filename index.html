Task 0071 · unified timer contract

Correct a running timer's start without stopping it

The baby fell asleep at 4:12 and the phone was reached at 4:31. Today that costs four steps: stop, delete the record, find the second button, re-enter the time. The running-timer view has no start-time display at all. This adds one tappable label — the value, the caregiver who started it — opening the picker the app already uses, bounded so nothing pickable is rejected afterwards.

Added

The range is shown, not corrected. Floor is the later of now − 12h and the end of the previous saved sleep; ceiling is now. A caregiver never picks a value the app then silently rewrites.

Twelve hours because that is the cleanup horizon. Previous-end because a running timer's anchor drives the widget, the Watch and the Live Activity and has no correction path until it stops — so overlap is put out of reach here, unlike saved records, which stay warn-and-allow.

Tightened

"Started earlier" gets the identical bounds. Its floor was yesterday midnight — up to forty-seven hours back. Leaving it would put a 12-hour edit bound and a 47-hour start bound on one screen.

Behind the pill

A direct UPDATE on active_timers.started_at — no new RPC, no policy change. The row policy is already USING (started_by = auth.uid()), and the sync engine replays queued writes as direct writes anyway, so an RPC would be an authority the replay path walks past. The server-side trigger stays the binding check.

Offline, the edit queues validated against now() at edit time and is revalidated at replay time — a long-queued edit can be rejected then. Stated consequence, not a defect.

Out of frame

Deliberately not in this screen.

  • Editing the stop time — refused separately.
  • Inline editing from the dashboard card, widget, Watch or Live Activity — the card keeps the read-only gate it applies today; the edit is reachable only from the starter's own running screen.
  • Editing a timer another caregiver started, or any widening of row access.
  • Clamping against activities of a different type — the floor is same-type only.
  • Saved-record clock-time editing — Tasks 0072 through 0074.
